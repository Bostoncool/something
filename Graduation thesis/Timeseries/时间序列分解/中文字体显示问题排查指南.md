# Matplotlib 中文字体显示问题排查指南

> 本文档汇总了三大城市群相关脚本中，Matplotlib 图表中文显示异常（方框、SVG「乱码」、**`¤` / STIX** 等）的成因、脚本差异、解决方案及验证方法；含 **统计趋势检验** 与参考脚本 **`AQI VS PM2.5.py`**（Unicode 化学式、Windows **`addfont`**、可解析字体链）、**西文 Times New Roman + 中文** 混排与 **`svg.fonttype`** 配置；**§2.5** 专门说明「一改 PM₂.₅ 就觉得中文坏了」的常见误判与真实原因。

---

## 一、问题现象

- **正常表现**：图表中的中文标题、坐标轴标签、图例等正确显示为汉字。
- **异常表现 A（缺字）**：中文被渲染为小方框（□），即字体缺失时的占位符。
- **异常表现 B（SVG 看起来像乱码，但不是 UTF-8 坏了）**：用浏览器、Word 或 Illustrator 打开 `.svg` 时，中文像错位、重复空心框或完全不像汉字；用编辑器打开同一文件，**声明为 `encoding="utf-8"`，且 `<!-- 注释 -->` 里的中文正常**。这通常不是「文件编码损坏」，而是 **文字被转成了错误的矢量路径**（见 §2.3）。
- **异常表现 C（中文变成 `¤` 或 STIX 字体）**：标题、轴标签、图例里本应显示汉字的位置出现 **货币符号 `¤`**，或 SVG 里对应 `tspan` 的 `font-family` 为 **`STIXGeneral`**。常见于 **同一字符串里混用了 mathtext 的 `$...$` 与普通中文**（见 §2.4）。
- **异常表现 D（与「改 PM2.5」同时被注意到）**：刚把图题里的 PM2.5 改成下标后，**中文变方框或 `¤`**。多为 **§2.4 的 mathtext**、**字体 rc 被误改**、**脚本编码** 或 **Word 打开 SVG 的字体策略**（§2.3.1、§2.5），**不是** Unicode 下标本身「关掉」了中文字体。

---

## 二、中文字体报错 / 方框的常见原因

### 2.1 根本原因

Matplotlib 默认使用 **DejaVu Sans** 等西文字体，**不支持中文字符**。当未正确指定中文字体时，系统会回退到这些字体，导致中文无法渲染，显示为方框。

### 2.2 具体诱因

| 诱因 | 说明 |
|------|------|
| 未设置中文字体 | `rcParams` 中未配置支持中文的字体 |
| 字体链被覆盖 | 使用 `sns.set_theme()` 等操作后，主题可能重置 `font.sans-serif` |
| 自动选择失败 | 动态探测字体时，若未检测到可用中文字体，回退到 `DejaVu Sans` |
| 输出格式差异 | PNG 在保存时即栅格化，字体缺失会直接变成方框；SVG 为矢量，部分查看器可能做字体替换，表现可能不同 |

### 2.3 SVG 默认把文字转成 path 时，西文字体对汉字的「伪轮廓」（易误判为乱码）

默认情况下，Matplotlib 保存 SVG 会使用 **`svg.fonttype` 的 path 模式**（将每个字变成 `<path>`，便于在没有安装对应字体的环境中仍显示「某种形状」）。

若此时 **`font.serif` / 实际选用的第一字体为 Times New Roman 等西文字体**，且该字体对 CJK 码位在底层返回了 **占位用轮廓**（例如多个不同汉字对应 **完全相同** 的矩形路径），则导出的 SVG 里会出现类似 `TimesNewRomanPSMT-xxxx`（`xxxx` 为 Unicode 十六进制）的 path，**视觉上像乱码或一堆框**，与 XML 声明、注释是否正常无关。

**与「方框（□）」的区别**：方框多表示当前渲染路径上**真的缺字**；本现象是 **path 已生成，但轮廓错误**，在矢量软件里仍是一堆 path，而不是缺字方框。

**对策概要**：

1. 设置 **`mpl.rcParams["svg.fonttype"] = "none"`**，让 SVG 保留 **`<text>` + `font-family`**，由查看器调用本机已安装字体绘制（Windows 上一般能正确显示中文）。
2. 需要 **英文 Times New Roman、中文楷体** 时，使用 Matplotlib **3.6+** 的 **按字形回退**：把 `font.family` 设为 **具体字体名的列表**（见 §6.2），而不是仅把楷体排在西文字体后面却仍以 path 模式烧进错误轮廓。

**`svg.fonttype = "none"` 的代价**：在未安装中文字体的电脑上打开该 SVG，中文仍可能缺失或回退异常；若需要「单文件、完全不依赖系统字体」的 SVG，需改用能嵌入子集轮廓的方案，并保证 **参与 path 化的字体本身含完整汉字字形**（勿让西文字体参与汉字 path）。

#### 2.3.1 补充：`fonttype = "none"` 时汉字仍是一格一格方框（□）

此时 SVG 里往往是 **`<text>…</text>`**，且 `style` 里 `font-family` **第一项为 `Times New Roman`**（因为作图时西文优先）。**浏览器**多数能按字做 fallback，用后面的 `KaiTi` / `Microsoft YaHei` 画中文；但 **Word、部分 PDF/矢量工具** 会把整段文字绑在**列表第一个字体**上。TNR 没有对应汉字字形时，就会显示为 **一个个方格（缺字占位）**，这与 UTF-8 损坏无关，也不是 §2.3 的 path 伪轮廓问题。

**对策**：

1. **插入论文**：优先用同目录下的 **PNG**（栅格化时已按 Matplotlib 字形回退正确渲染），或 **在 Word 中换用中文字体** 再编辑 SVG 文字。
2. **从脚本侧**：在保存 SVG 之后，把文件内 `font-family` **重写为「中文字体名在前、Times New Roman 在后」**（`三大城市群（日）MSTL.py` / `三大城市群（月）STL.py` 的 `save_figure_dual` 已做后处理；若需保留 Matplotlib 原顺序，可设 **`MSTL_SVG_NO_FONT_REORDER=1`** 或 **`STL_SVG_NO_FONT_REORDER=1`**）。注意：调整后 **SVG 内西文在部分软件里可能随首项中文字体显示**，与 PNG 中「纯 TNR 西文」可能略有差异；**PNG 仍以 rcParams 为准**。

### 2.4 mathtext（`$...$`）与中文混排 → STIX 缺字占位 `¤`

只要字符串里出现 **`$...$`**，Matplotlib 会启用 **mathtext** 参与排版。若 **图题、纵轴标签** 等写成 **`"中文" + r"$\mathrm{PM}_{2.5}$" + "更多中文"`** 或 **`$\mathrm{PM}_{2.5}$浓度`** 这类形式，**夹在数学段之间或紧随 mathtext 的中文** 仍可能走 mathtext/STIX 的字体与缺字逻辑，结果在 SVG 里变成 **`font-family: STIXGeneral`** 与 **`¤`**（缺字形占位），而不是方框 □。

**与 §2.3 的区别**：§2.3 是 **path 模式 + 西文伪轮廓**；本节是 **mathtext 路径下中文未映射到 CJK 字体**。

**对策（推荐，与正常脚本 `AQI VS PM2.5.py` 一致）**：

1. **凡与中文出现在同一 `Text` 里的 PM₂.₅，不要用 `$...$`**，改用 **Unicode 下标**：`PM25_UNICODE = "PM\u2082.\u2085"`（即 **PM₂.₅**）。
2. 单位如 **(μg/m³)** 可写成 **纯 Unicode**：`"(\u03bcg/m\u00b3)"`，保证 **整段标签不含 `$`**，则走普通文本的 `font.family` 回退（TNR + 雅黑等），中文不再进 STIX。
3. 若仍需独立公式行且仅含拉丁/希腊，可单独使用 mathtext，**避免与中文拼接在同一字符串**。

统计趋势检验脚本 **`可视化作图.py`** 已按上述方式改为 **`PM25_PLAIN` + `LABEL_UNIT_UGM3`**，与参考脚本思路一致。

### 2.5 「一改 PM2.5，中文就不能用了」：原因辨析（重要）

很多人会在**同一轮修改**里同时动「化学式/下标」和「字体、保存方式、用哪个软件看图」，于是直觉上认为 **「就是改成 PM₂.₅ 把中文搞坏的」**。实际上 **Unicode 的 PM₂.₅ 本身不会“关闭”中文字体**；常见真实原因在下面几条里，请按顺序对照。

#### 2.5.1 根因一（最常见）：用了 mathtext 的 `$...$`，而不是 Unicode 下标

为了排出漂亮的「2.5 下标」，若写成 **`r"$\mathrm{PM}_{2.5}$"`** 或与中文拼在同一串里出现 **`$...$`**，会触发 **§2.4** 整条链路：**STIX / `¤` / 中文缺字**，表现与「中文坏了」几乎一样。  
**这与「改成 PM₂.₅」在现象上无法区分**，除非检查源码里是否还有 **`$`**。

- **自检**：全项目搜索图题、轴标签字符串里的 **`$`**；在导出的 SVG 里搜索 **`STIXGeneral`**、**`¤`**（见 §6.4）。
- **正确做法**：仅用 **`PM25_UNICODE = "PM\u2082.\u2085"`**，且**整段标签不要出现 `$`**。

#### 2.5.2 根因二：同一轮编辑里误伤了字体配置（相关 ≠ 因果）

改标题时**复制粘贴、合并分支、只拷了半段 `configure_plot_fonts`**，导致 **`sns.set_theme` 后又没设中文字体链**、或 **`font.serif` / `font.family` 被覆盖**，PNG 里也会全体中文方框。  
用户往往只记得「我刚改了 PM2.5」，**实际是字体 rc 被改坏了**。

- **自检**：运行前打印 `plt.rcParams["font.family"]`、`plt.rcParams["font.serif"]`（或 `font.sans-serif`），确认链里仍有 **KaiTi / 雅黑 / 黑体** 等；确认 **`configure_plot_fonts()` 在作图前调用且位于 `sns.set_theme` 之后**（见 §6.1）。

#### 2.5.3 根因三：脚本文件编码被保存错（中文源码变乱码）

在含有 **`PM25_UNICODE`** 或 **`f"…{PM25_UNICODE}…"`** 的同一文件里编辑时，若编辑器把 **`.py` 存成非 UTF-8**（如误选 ANSI、部分环境默认 GBK 与 UTF-8 混用），**文件中所有中文**（图题里的「三大城市群」等）在运行或再次打开时都会异常。用户也会误以为是「下标导致的」。

- **自检**：用编辑器看文件编码是否为 **UTF-8**；Git diff 是否突然出现大量中文乱码。

#### 2.5.4 根因四（SVG + Word 高发）：图题里拉丁字母变多后，整段被当成「西文段落」

规范写法下，图题类似：**`三大城市群 PM₂.₅ MSTL 趋势项对比`**——同一段 `<text>` 里既有汉字，又有 **PM、MSTL** 和 **Unicode 下标**（U+2082、U+2085）。  
在 **§2.3.1** 已说明：Word 等对 **`font-family` 列表第一项** 处理很差。除此之外，部分版本还会按 **「拉丁字母比例」** 把整段判为西文，**强行用 Times New Roman 绘整段**，汉字就变成 **方格**。  
**纯中文**的轴标签（如「趋势项」「时间」）反而正常，于是特别容易让人以为是 **「加了 PM2.5 才坏」**——其实是 **「含 PM₂.₅ 的那一行图题」在 Word 里更触发劣质排版**。

- **自检**：同一 SVG 用 **Chrome / Edge** 打开：若浏览器正常、仅 Word 方框，即属 **查看器/导入逻辑**，不是 Matplotlib 没写出汉字。
- **示例（正常文件长什么样）**：`三大城市群_MSTL趋势对比.svg` 中图题一行在 XML 里应为合法 UTF-8 汉字 + **`PM₂.₅`**（Unicode 字符，不是图片），且 `font-family` 在脚本后处理后宜以 **中文字体** 开头，例如（节选）：

```xml
<text ... font-family: 'Microsoft YaHei', 'KaiTi', ... >三大城市群 PM₂.₅ MSTL 趋势项对比</text>
```

若你看到的 **`font-family` 仍以 `Times New Roman` 为第一项**，且只在 Word 里方框，请先完成 **§2.3.1** 的 SVG 后处理或改用 **PNG** 插入 Word。

#### 2.5.5 根因五（较少见）：下标码位与字体覆盖

**U+2082（下标 2）、U+2085（下标 5）** 属于「上标与下标」区块。绝大多数 **Windows 自带的 Times New Roman、微软雅黑、楷体** 都带这两个码位；若某台机器缺字，通常只影响 **₂、₅ 两个小字**，**不应**导致整句中文变方框。若出现「只有下标是框、中文正常」或相反，再查 **具体字体安装与 `findfont` 结果**。

#### 2.5.6 小结表

| 现象 | 更可能的根因 | 建议自检 |
|------|----------------|----------|
| SVG 里出现 **`¤` / `STIXGeneral`** | **mathtext `$...$`**（§2.4） | 去掉 `$`，改用 **`PM\u2082.\u2085`** |
| PNG 里中文也方框 | **字体 rc 未配置或被覆盖**（§2.2、§6.1） | 查 `configure_plot_fonts` 与 `font.serif` 链 |
| 源码里中文乱码 | **`.py` 编码非 UTF-8**（§2.5.3） | 文件另存为 UTF-8 |
| 仅 Word 里图题方框，浏览器正常 | **Word 对 SVG 文本/字体策略**（§2.3.1、§2.5.4） | 用 **PNG** 或 **font-family 中文优先** 的 SVG |
| 仅含 PM₂.₅ 的图题坏，纯中文标签好 | 同上，**图题拉丁成分多** 更易触发 | 同上 |

**结论**：**规范的 Unicode PM₂.₅ 不会单独「禁用」中文**；若一改 PM2.5 就出问题，请按上表把 **mathtext、rcParams、文件编码、SVG 查看软件** 四条线分开排查，避免把多种问题混成一个「下标惹祸」的错觉。

## 四、导致变成方框的原因（汇总）

1. **字体链中优先使用了不支持中文的字体**（如 `DejaVu Sans`）作为首选或回退。
2. **自动探测失败**：本机未安装预设的中文字体，或探测逻辑有误，导致选中了西文字体。
3. **Seaborn 主题覆盖**：`sns.set_theme()` 在设置字体之后执行，或通过 `rc=plt.rcParams` 传入时，主题内部可能重置 `font.sans-serif`。
4. **PNG 输出**：保存为 PNG 时，字体信息在生成时即被栅格化，一旦字体错误就无法补救。

---

## 五、不变成方框的原因（正常脚本为何正常）

1. **固定中文字体链**：明确使用 `SimHei`、`Microsoft YaHei` 等支持中文的字体，不依赖自动探测。
2. **无 Seaborn 主题覆盖**：仅设置 `mpl.rcParams`，不调用会重置字体的 theme。
3. **SVG 输出**：矢量格式对字体依赖更友好，部分场景下即使配置略有偏差，查看器也可能做字体替换。

## 六、修改方案（推荐做法）

### 6.1 字体配置（核心）

```python
import matplotlib as mpl
import matplotlib.pyplot as plt
import seaborn as sns

# 1. 先设置 seaborn 主题（若有使用）
sns.set_theme(style="whitegrid")

# 2. 再强制覆盖字体相关 rc，避免被 theme 重置
chinese_font_chain = [
    "SimHei",
    "Microsoft YaHei",
    "Arial Unicode MS",
    "SimSun",
    "Noto Sans CJK SC",
    "Source Han Sans SC",
]
mpl.rcParams["font.family"] = "sans-serif"
mpl.rcParams["font.sans-serif"] = chinese_font_chain
mpl.rcParams["axes.unicode_minus"] = False  # 负号显示正常
```

**要点**：
- 使用**固定字体链**，不要用 `DejaVu Sans` 作为首选。
- 若使用 seaborn，**先** `sns.set_theme()`，**再**设置字体 rc。
- `axes.unicode_minus = False` 可避免负号显示异常。

### 6.2 SVG 避免「伪汉字 path」+ 西文 TNR 与中文楷体混排（Matplotlib ≥ 3.6）

适用于毕业论文图：**正文与坐标轴中的拉丁字母、数字用 Times New Roman，汉字用楷体**。利用 **`font.family` 为「字体名列表」** 时的 **按字形回退**（先尝试列表前者，缺字再用后者）：

```python
import matplotlib as mpl

mpl.rcParams["svg.fonttype"] = "none"  # 避免 path 模式下西文对汉字生成占位轮廓
mpl.rcParams["font.family"] = [
    "Times New Roman",
    "KaiTi",
    "STKaiti",
    "SimKai",
    "KaiTi_GB2312",  # 部分系统上楷体的注册名
]
mpl.rcParams["axes.unicode_minus"] = False

# 化学式等 mathtext 仍指定 Times New Roman（与正文西文一致）
mpl.rcParams["mathtext.fontset"] = "custom"
mpl.rcParams["mathtext.rm"] = "Times New Roman"
mpl.rcParams["mathtext.it"] = "Times New Roman:italic"
mpl.rcParams["mathtext.bf"] = "Times New Roman:bold"
```

**注意**：

- **`font.family` 必须直接设为上述字体名列表**（与 `AQI VS PM2.5.py` 的 `build_thesis_figure_font_family()` 一致），**不要**写成 `font.family = "serif"` 再只配 `font.serif = [...]`。在后一种写法下，部分 Matplotlib 版本在 **PNG 栅格化**时会把整段文字优先绑在 **Times New Roman**，**不按字符回退**到链中的楷体/雅黑，表现为 **中文全体方框**，控制台可能出现 **`Glyph ... missing from font(s) Times New Roman`**。
- 若控制台反复出现 `Font family 'KaiTi' not found`，除安装楷体外，可参考 **`AQI VS PM2.5.py`** 的 **`addfont` + `build_thesis_figure_font_family()`**（§3.4）：在 Windows 上把 **`simkai.ttf` / `msyh.ttc`** 等注册进 Matplotlib，并**只把 `findfont` 能解析的名称**放进 `font.family`。**统计趋势检验** 脚本使用 **`ttflist` 过滤已登记名称** 的写法，与「只加可解析字体」目的一致；若仍解析不到楷体，可合并 **addfont** 逻辑。
- **勿**在含中文的标题/轴标签里使用 **`$\mathrm{PM}_{2.5}$` + 中文** 的拼接；应改用 **Unicode `PM\u2082.\u2085`**（§2.4、§3.4）。

### 6.3 同时输出 PNG 与 SVG（论文推荐）

```python
def save_figure_dual(fig, save_path_png: str, dpi: int = 300) -> None:
    """同时保存 PNG 与 SVG 版本。"""
    fig.savefig(save_path_png, dpi=dpi, bbox_inches="tight")
    save_path_svg = os.path.splitext(save_path_png)[0] + ".svg"
    fig.savefig(save_path_svg, format="svg", bbox_inches="tight")
```

- **PNG**：便于预览、插入 PPT 等。
- **SVG**：矢量图，适合论文排版，可无损缩放；在已设置 `svg.fonttype = "none"` 时，**依赖查看端已安装 `font-family` 中列出的字体**；若仍为 path 模式，则需关注 §2.3 的西文伪轮廓问题。

### 6.4 mathtext 与中文：问题与写法对照

| 不推荐 | 推荐 |
|--------|------|
| `r"$\mathrm{PM}_{2.5}$" + "浓度 (μg/m³)"`（易出现 `¤`） | `"PM\u2082.\u2085" + "浓度 " + "(\u03bcg/m\u00b3)"` |
| 图题：`"三大城市群季度" + PM25_MATH + "浓度变化"` | `"三大城市群季度" + "PM\u2082.\u2085" + "浓度变化"` |

导出 SVG 后可用编辑器搜索 **`STIXGeneral`**、**`¤`** 做快速验收。

### 6.5 控制台中文输出（可选）

若终端编码导致 `print` 中文报 `UnicodeEncodeError`，可使用安全输出：

```python
def safe_print(message: str) -> None:
    try:
        print(message)
    except UnicodeEncodeError:
        print(message.encode("ascii", errors="backslashreplace").decode("ascii"))
```

## 七、快速排查清单

遇到“中文变方框”时，按以下顺序检查：

| 序号 | 检查项 | 操作 |
|------|--------|------|
| 1 | 当前字体链 | 打印 `plt.rcParams["font.sans-serif"]`，确认是否包含 SimHei、Microsoft YaHei 等 |
| 2 | 本机可用字体 | `from matplotlib import font_manager; print([f.name for f in font_manager.fontManager.ttflist if "Hei" in f.name or "YaHei" in f.name])` |
| 3 | Seaborn 覆盖 | 若用了 `sns.set_theme()`，确保**在其之后**再次设置 `font.sans-serif` |
| 4 | 输出格式 | 尝试保存为 SVG，对比 PNG 是否仍有方框 |
| 5 | 字体安装 | Windows 可安装「微软雅黑」「黑体」等，确保系统中有至少一种中文字体 |
| 6 | SVG「乱码」 | 用编辑器搜 `TimesNewRomanPSMT-` 或观察多个汉字的 `<path d="...">` 是否完全相同；若是，检查 `svg.fonttype` 与字体链（§2.3、§6.2） |
| 7 | 混排需求 | 需要 TNR+楷体时，用 `font.family = [...]` 列表而非仅 `font.serif` 里 TNR 置顶且仍用 path 导出 |
| 8 | 中文变 `¤` | 搜 SVG 中 **`STIXGeneral`** / **`¤`**；检查图题/轴标签是否含 **`$...$` 与中文同串**，改为 **Unicode PM₂.₅**（§2.4、§6.4） |
| 9 | KaiTi 找不到 | 尝试 **`AQI VS PM2.5.py` 式 `addfont` + 可解析字体列表**（§3.4） |
| 10 | SVG 在 Word 里中文方格 | 已 `svg.fonttype=none` 且 `<text>` 内汉字正常时，多为 **只认 `font-family` 第一项**（§2.3.1）；用 **PNG** 或 **保存后把中文字体提前**（如 MSTL 脚本 `save_figure_dual` 后处理，或设 `MSTL_SVG_NO_FONT_REORDER=1` 保留原顺序） |
| 11 | 改完 PM₂.₅ 中文就坏 | **先读 §2.5**：区分 **mathtext `$`**（§2.4）、**rc 被覆盖**、**`.py` 编码**、**Word 打开 SVG**（§2.3.1）；Unicode **`PM\u2082.\u2085`** 本身不禁用中文 |
